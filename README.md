# Склад

Офлайн-приложение для Android: фотографируем **одинаковые бумажные расходные накладные**, проверяем распознанные коды/веса и автоматически считаем, **сколько мешков каждого товара собрать**.

## Установка

Готовый APK: [GitHub Actions — успешная сборка](https://github.com/arladiy96-commits/Sklad/actions/runs/40456938433). В разделе **Artifacts** скачай **Sklad-Android-APK**, распакуй ZIP и установи файл app-release.apk на Android.

Сборка прошла: Flutter analyze, тесты, Android release APK. Точность сканирования на устройстве ещё требует проверки на реальных накладных.

## Возможности первой версии

- Камера или импорт фотографии из галереи; поиск ориентации листа 0/90/180/270 градусов.
- Локальное распознавание ML Kit (без Gemini, облачных квот и постоянного интернета).
- Таблица результатов с кодами товаров, весом в кг, ценой, суммой; ручное исправление.
- Автоматический перевод кг в штуки по фасовке. Проверка кратности фасовке и цены × веса = суммы, если оба значения доступны.
- Проверка дублирующихся номеров накладных внутри текущей сборки.
- Встроенный справочник товаров (пока 7 кодов по присланным накладным); добавление и изменение через вкладку «Товары».
- Суммарная ведомость с каждым слагаемым, итогами и экспортом PDF/печатью.
- Завершение текущей сборки, новая сборка, просмотр и восстановление истории.
- Исходные фотографии, позиции, справочник и история хранятся локально на телефоне.

**Важно:** OCR может пропустить целую строку или неверно прочитать цифры. После сканирования нужно сверить **все строки** и поставить галочку подтверждения. Автоподсчёт не заменяет проверку кладовщиком. Обнаружение границ и автосъёмка без нажатия пока не реализованы — в первой версии камера вызывается обычным системным интерфейсом.

## Разработчику

Исходники Flutter находятся в \`lib/\`, ассортимент — \`assets/catalog/products.json\`. Для локальной работы после клонирования (если папка android ещё не создана):

\`\`\`bash
flutter create --platforms=android --project-name sklad --org kz.sklad .
flutter pub get
flutter run
\`\`\`

GitHub Actions сам генерирует Android-проект, задаёт minSdk 24, и добавляет ProGuard-правила для необязательных языковых модулей ML Kit перед сборкой APK.

**Тестовая версия.** Первая установка для проверки на складе. Для долгосрочной системы обновлений потребуется постоянный ключ подписи Android (сейчас используется конфигурация отладочной подписи шаблона Flutter).

## Инвентаризация · версия 0.2

Нижняя вкладка **«Инвентаризация»** полностью отделена от старых накладных и сборочных ведомостей.

- **Товары:** карточки с названием, единицей (шт, кг, мешки), категорией и местом хранения. Можно отдельно скопировать номенклатуру из накладных; начальные остатки будут нулевыми.
- **Коды:** собственный внутренний код `SK-000001`, по которому создаются QR и Code 128; этикетка в PDF с возможностью печати. К товару можно привязать несколько заводских EAN / Code 128 / QR и вручную введённых кодов; один код не может принадлежать двум карточкам.
- **Сканер:** камера автоматически распознаёт QR и популярные 1D-коды (ML Kit); если код новый, предлагает создать карточку. Есть ручной ввод на случай плохого освещения или повреждённой этикетки.
- **Остатки:** приход/расход с примечанием, проверка доступного количества, история движений. Накладные **не** списывают остатки автоматически — это отдельный экспериментальный модуль.
- **Пересчёт:** открываем сессию с фиксированными остатками, сканируем товар и записываем **фактическое количество** (повторное сканирование заменяет число, а не прибавляет). Непроверенные товары не считаются отсутствующими. Закрываем сессию с применением корректировок либо только с отчётом. Во время сессии приход и расход заблокированы.
- **История и экспорт:** завершённые и отменённые инвентаризации, сравнение «учёт/факт/расхождение», отчёт CSV для Excel и полная резервная копия JSON через системное меню «Поделиться».

### Важные ограничения тестовой версии

Инвентаризация хранится **локально только на данном телефоне** в `sklad_inventory_v1.json` в приватных документах приложения. Между устройствами нет синхронизации, пользователей и ролей пока нет. Не используй её как единственный учёт реальных товарных остатков: для промышленной версии понадобятся серверная база, права сотрудников, атомарные транзакции, синхронизация и автоматические резервные копии.

**Перед удалением приложения обязательно экспортируй JSON-копию.** Обычное удаление Android-приложения может удалить его локальную базу.

Проверка: создать товар сканированием заводского кода → записать приход 10 → открыть пересчёт → отсканировать его повторно → записать факт 8 → завершить с применением → увидеть остаток 8 и движение -2. Затем вывести QR/Code 128 на экран или этикетку PDF и прочитать камерой другого устройства.

Временная сборка APK доступна через [GitHub Actions](https://github.com/arladiy96-commits/Sklad/actions). Модуль специально добавлен отдельно, чтобы не изменять существующий процесс накладных.
